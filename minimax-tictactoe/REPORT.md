# Отчёт: ИИ для крестиков-ноликов на алгоритме Minimax

## 1. Описание игры

Выбран **вариант 1 — крестики-нолики 3×3**. Два игрока по очереди ставят свой знак
(`X` — человек, `O` — ИИ) в свободную клетку поля 3×3. Побеждает тот, кто первым
займёт три клетки подряд по горизонтали, вертикали или диагонали. Если поле
заполнено, а победителя нет, — ничья.

Реализация на C# (`TicTacToe.cs` — логика и ИИ, `Program.cs` — консольная игра).
Логика не зависит от консоли, поэтому её можно использовать и в Unity
(`Unity/TicTacToeUnity.cs`).

| Компонент | Функция |
|---|---|
| структура игрового состояния | класс `GameState` (доска `char[9]` + чей ход) |
| получение допустимых ходов | `GetMoves(state)` — индексы пустых клеток |
| применение хода | `ApplyMove(state, move)` — возвращает новое состояние |
| проверка терминального состояния | `IsTerminal(state)`, `Winner(state)` |
| оценочная функция | `Evaluate(state)` |
| Minimax | `Minimax(state, depth, isMaximizing)` |
| выбор хода ИИ | `BestMove(state, out scores)` |
| режим «человек против ИИ» | `Program.Play()` |

## 2. Как работает Minimax

Minimax рассматривает игру как дерево: корень — текущая позиция, дочерние узлы —
позиции после каждого возможного хода, листья — терминальные позиции (победа,
поражение, ничья).

Игроки называются так:

- **MAX** — ИИ, стремится сделать оценку как можно больше;
- **MIN** — человек, по предположению играет идеально и стремится сделать оценку
  ИИ как можно меньше.

Алгоритм рекурсивный:

```csharp
public static int Minimax(GameState state, int depth, bool isMaximizing)
{
    if (IsTerminal(state))
    {
        int score = Evaluate(state);
        if (score > 0) return score - depth;
        if (score < 0) return score + depth;
        return 0;
    }
    if (isMaximizing)  // ход ИИ — берём максимум
    {
        int best = int.MinValue;
        foreach (int move in GetMoves(state))
            best = Math.Max(best, Minimax(ApplyMove(state, move), depth + 1, false));
        return best;
    }
    else               // ход человека — берём минимум
    {
        int best = int.MaxValue;
        foreach (int move in GetMoves(state))
            best = Math.Min(best, Minimax(ApplyMove(state, move), depth + 1, true));
        return best;
    }
}
```

Оценки «поднимаются» от листьев к корню: на уровнях ИИ берётся максимум, на уровнях
человека — минимум. Так ИИ для каждого своего хода узнаёт, какой результат он
гарантированно получит, **даже если соперник ответит наилучшим для себя образом**,
и выбирает ход с максимальной гарантированной оценкой (`BestMove`).

В крестиках-ноликах всего 9! = 362 880 последовательностей ходов (на деле меньше, т.к.
многие партии заканчиваются раньше), поэтому выполняется **полный перебор** дерева
без ограничения глубины: первый ход ИИ на пустой доске просматривает ≈550 тыс. узлов
и занимает доли секунды.

Так как крестики-нолики при идеальной игре обеих сторон заканчиваются ничьей, а
Minimax находит именно идеальную игру, ИИ **никогда не проигрывает**. Это проверено
программно (`dotnet run -- --test`): перебраны все возможные стратегии
человека при обоих вариантах очерёдности — 642 партии, из них 457 побед ИИ,
185 ничьих, 0 поражений.

## 3. Оценочная функция

`Evaluate(state)` оценивает терминальную позицию с точки зрения ИИ:

| Исход | Оценка |
|---|---|
| победа ИИ | `+10` |
| победа человека | `−10` |
| ничья | `0` |

Дополнительно в `Minimax` к оценке применяется поправка на глубину `depth`
(число ходов от текущей позиции до конца партии):

- победа: `10 − depth` — быстрая победа ценнее долгой;
- поражение: `−10 + depth` — если проигрыш неизбежен, его стоит отсрочить;
- ничья: `0`.

Знак оценки не меняется (победа всегда > 0, поражение < 0), поэтому базовая шкала
`+10 / −10 / 0` сохраняется. Без поправки ИИ видел бы несколько одинаково
выигрышных ходов и мог бы выбрать «медленный», затягивая партию.

## 4. Пример хода ИИ

Человек ходит первым в угол (клетка 1). Вывод программы:

```
 X | 2 | 3
---+---+---
 4 | 5 | 6
---+---+---
 7 | 8 | 9

ИИ анализирует ходы (просмотрено узлов дерева: 59704):
  клетка 2: оценка -4 (победа человека)
  клетка 3: оценка -4 (победа человека)
  клетка 4: оценка -4 (победа человека)
  клетка 5: оценка +0 (ничья)  <- выбран
  клетка 6: оценка -4 (победа человека)
  клетка 7: оценка -4 (победа человека)
  клетка 8: оценка -4 (победа человека)
  клетка 9: оценка -4 (победа человека)
ИИ ходит в клетку 5
```

**Почему выбран центр.** На ход в угол единственный ответ, не ведущий к поражению, —
центр. При любом другом ответе человек может построить «вилку» — позицию с двумя
угрозами одновременно, обе закрыть нельзя. Minimax это обнаружил: для всех клеток,
кроме 5, на минимизирующем уровне нашлась такая последовательность ходов человека,
которая ведёт к победе `X` через 6 ходов (оценка `−10 + 6 = −4`). Для клетки 5 лучшее,
чего может добиться человек, — ничья (`0`). Максимум из `{−4, 0}` — это `0`.

Продолжение партии: человек ставит `X` в клетку 9 (противоположный угол).

```
ИИ анализирует ходы (просмотрено узлов дерева: 1052):
  клетка 2: оценка +0 (ничья)  <- выбран
  клетка 3: оценка -6 (победа человека)
  клетка 4: оценка +0 (ничья)
  клетка 6: оценка +0 (ничья)
  клетка 7: оценка -6 (победа человека)
  клетка 8: оценка +0 (ничья)
```

Здесь классическая ловушка: ход в свободный угол (3 или 7) кажется естественным,
но проигрывает — `X` занимает другой угол и создаёт вилку. ИИ выбирает ход на сторону.

Человек ошибается и ходит в клетку 3, создавая угрозу 3–6–9:

```
 X | O | X
---+---+---
 4 | O | 6
---+---+---
 7 | 8 | X

ИИ анализирует ходы (просмотрено узлов дерева: 33):
  клетка 4: оценка -8 (победа человека)
  клетка 6: оценка +7 (победа ИИ)
  клетка 7: оценка -8 (победа человека)
  клетка 8: оценка +9 (победа ИИ)  <- выбран
ИИ ходит в клетку 8
```

Ход в 6 блокирует угрозу и тоже ведёт к победе, но позже (`+7`). Ход в 8 сразу
замыкает линию 2–5–8 (`10 − 1 = +9`). Благодаря поправке на глубину ИИ выбирает
немедленную победу.

## 5. Ограничение глубины поиска

Для крестиков-ноликов **глубина поиска не ограничивается**: дерево маленькое
(на пустой доске ≈550 тыс. узлов), поэтому полный перебор занимает доли секунды
и даёт точный результат. Именно полный перебор гарантирует, что ИИ никогда не
проигрывает.

В играх с большим деревом (Connect Four, шахматы) число позиций растёт
экспоненциально — примерно `b^d`, где `b` — среднее число ходов, `d` — глубина.
Полностью дерево там не перебрать, поэтому:

- поиск ограничивают глубиной `d` (например 3–5 ходов);
- в позициях на границе глубины, которые не являются терминальными, вместо
  точного исхода используют **эвристическую оценку** (материал, линии из 2–3 фишек,
  контроль центра и т.п.);
- для ускорения применяют альфа-бета отсечение, которое отбрасывает ветви, заведомо
  не влияющие на результат.

Цена ограничения — ИИ перестаёт быть идеальным: он не видит последствий
дальше горизонта поиска и полагается на приблизительную оценку.
